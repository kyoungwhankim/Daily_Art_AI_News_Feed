# 루틴 옮기기 · 새로 만들기 안내

매일 뉴스·서비스 업데이트·(주 1회) 무료 혜택을 모아 main에 올리는 작업은 claude.ai의 **루틴(Routines)** 이 돌린다.
계정을 바꾸거나 새 루틴으로 같은 작업을 이어 갈 때 맞춰야 할 것을 정리했다.

## 1. 프롬프트

- 루틴 프롬프트에는 `routine/trigger_prompt.txt` 내용을 **그대로** 붙여 넣는다.
- 이 짧은 프롬프트는 실행할 때마다 main을 받아 `routine/daily_feed_prompt.txt`를 읽고 따른다.
  실제 작업 내용(출처 목록, 섹션별 개수, 에이전트 실행 등)은 레포 파일만 고치면 다음 실행부터 반영된다.
- `{{date}}` 자리표시자는 그대로 둔다 (루틴이 실행 날짜로 바꿔 준다).
- 예전처럼 `daily_feed_prompt.txt` 전체를 루틴에 붙여 넣으면 레포를 고쳐도 루틴에 반영되지 않으니 하지 않는다.

## 2. 루틴 설정

| 항목 | 값 | 비고 |
|---|---|---|
| 실행 주기 | `1 0 * * *` | UTC 0시 1분 = 한국 시간 오전 9시 1분, 매일 |
| 모델 | Opus (지금 루틴과 같은 모델) | 업데이트 에이전트(Haiku)·무료 혜택 에이전트(Sonnet)·금주 리포트 에이전트(Sonnet)의 모델은 레포 프롬프트가 정한다 |
| 세션 | 실행할 때마다 새 세션 | 이어 쓰는 세션(persist)이 아니어도 된다 |
| 저장소 | `kyoungwhankim/Daily_Art_AI_News_Feed` | 프롬프트가 직접 clone하므로 환경에 미리 붙이지 않아도 된다 |

## 3. 환경(Environment)

- **환경 변수 `GITHUB_TOKEN`** (필수)
  - 이 레포에 **쓰기 권한**(contents: write)이 있는 GitHub 개인 액세스 토큰(PAT).
  - clone과 main 푸시(`scripts/push_to_main.py`)에 쓴다.
  - 다른 GitHub 계정의 토큰이라면, 그 계정이 이 레포의 협업자(쓰기 권한)여야 한다.
  - 토큰 값은 루틴 환경의 비밀 값(Secrets/환경 변수)에만 넣는다. 레포·채팅·이슈에 붙여 넣지 않는다.
  - 토큰에 만료일이 있으면 만료 전에 새로 발급해 바꿔 넣는다 (만료되면 푸시 단계에서 실패한다).
- **네트워크**: 뉴스 출처 사이트(국내외 매체), AI 서비스 공식 사이트, GitHub에 접속할 수 있어야 한다.
  지금 루틴 환경과 같은 네트워크 설정(인터넷 접속 허용)을 쓴다.
- **도구**: 기본 환경의 `git`, `python3`, `node`, `curl`이면 충분하다 (추가 설치 없음).

## 4. 옮길 때 순서

1. 새 계정(또는 새 루틴)의 환경에 `GITHUB_TOKEN`을 넣는다.
2. 새 루틴을 만들고 `routine/trigger_prompt.txt`를 붙여 넣는다. 실행 주기·모델을 위 표대로 맞춘다.
3. **기존 루틴을 끈다.** 둘이 같이 돌면 같은 날 두 번 수집해 서로 덮어쓰거나 푸시가 충돌한다.
4. 새 루틴을 한 번 수동으로 실행해 본다. 보고에서 확인할 것:
   - "Whitelist loaded:" 줄이 나오고 출처 수가 맞는지
   - 기사 저장과 `validate_data.py`의 "✅ data/ is valid"
   - 마지막 푸시가 성공했는지 (main에 새 커밋이 생겼는지)
5. 다음 날 정해진 시각에 자동으로 돌았는지 한 번 더 확인한다.

## 5. 루틴과 상관없는 것 (옮길 필요 없음)

- Cloudflare Pages 배포, 주간 Supabase 깨우기(`supabase-keepalive.yml`), 업데이트 출처 점검(`check-update-sources.yml`) — GitHub Actions에서 돈다.
- 회원 로그인(Supabase · Google Cloud), AdSense — 사이트 설정이라 루틴 계정과 무관하다.

## 6. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| clone·push 실패 (401/403) | `GITHUB_TOKEN`이 있는지, 만료되지 않았는지, 이 레포 쓰기 권한이 있는지 |
| 기사 0개, 출처 접속 실패가 많음 | 환경 네트워크 설정이 인터넷 접속을 막고 있지 않은지 |
| 같은 날 커밋이 두 번 / 푸시 충돌 | 예전 루틴이 꺼져 있는지 |
| 레포를 고쳤는데 반영이 안 됨 | 루틴 프롬프트가 `trigger_prompt.txt`(불러오기용)인지, 고친 내용이 main에 올라갔는지 |
