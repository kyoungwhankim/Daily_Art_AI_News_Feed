AI Art Daily — daily routine for Google Antigravity (Gemini) on Windows

The Antigravity Automation only loads this file. This file runs the SAME routine as the Claude
routine — routine/daily_feed_prompt.txt and the three agent prompts it names — and lists what
to do differently here (Windows PowerShell, no sub-agents, local GitHub login).

This run is unattended — nobody is watching. Never stop to ask a question or wait for a
confirmation. Finish the whole routine.

=====================================================================
SETUP — run these first, one command at a time
=====================================================================

The Automation prompt already moved the terminal to the repository and reset it to main.
`git reset --hard` keeps new files that an earlier (test) run left in data/, so remove them
first — otherwise they would be published with today's push:

git clean -fdq data

Then check the environment and get today's date:

Get-Location
Set-Location '<REPO_DIR>'; [Console]::OutputEncoding = [Text.Encoding]::UTF8; $env:PYTHONUTF8 = "1"; python scripts/run.py scripts/routine_steps.py env-check
Set-Location '<REPO_DIR>'; [Console]::OutputEncoding = [Text.Encoding]::UTF8; $env:PYTHONUTF8 = "1"; python scripts/run.py scripts/routine_steps.py today
Set-Location '<REPO_DIR>'; [Console]::OutputEncoding = [Text.Encoding]::UTF8; $env:PYTHONUTF8 = "1"; python scripts/run.py scripts/routine_steps.py paths

- `Get-Location` prints REPO_DIR (the repository folder). Write it literally in place of
  <REPO_DIR>.
- Each terminal call may start a fresh PowerShell session in another folder and with the
  console's old code page. So EVERY python command in this routine starts with the prefix
      Set-Location '<REPO_DIR>'; [Console]::OutputEncoding = [Text.Encoding]::UTF8; $env:PYTHONUTF8 = "1";
  (rule W1). Without it Korean / Japanese / Chinese text in the output turns into "?�" and the
  work files may land on another drive.
- env-check prints a line "Text check: 한국어 · 日本語 · 中文 · Größe". If you do not see those
  exact characters, the prefix is missing — fix it before going on. You must be able to read
  Korean, Japanese, Chinese and German source text correctly.
- env-check also checks that the repository is exactly origin/main ("git : up to date"). If it
  says NOT up to date, run (one per line) `git rebase --abort`, `git checkout -f main`,
  `git reset --hard origin/main`, then re-read this file from the top — an old checkout means old
  instructions and old scripts.
- env-check must end with "Environment OK.". If it still fails (python, git, curl or node
  missing), stop and report the failing line.
- `today` prints TODAY (KST, YYYY-MM-DD). Use it wherever the files say {{date}}.
- `paths` prints where the work folders really are on this computer (e.g. /tmp/feed is
  C:\tmp\feed). Call that folder WORK_FEED; the others WORK_UPDATES, WORK_FREE, WORK_REPORT.
- The repository folder (`Get-Location`) is REPO_DIR.

Then read routine/daily_feed_prompt.txt in full (it is long — read it in parts until you
reach its FINISH section), and follow it from its first line to FINISH with the rules below.

=====================================================================
WINDOWS RULES (W) — how to run the commands written in the routine files
=====================================================================

The routine files were written for a Linux bash shell. Your terminal is Windows PowerShell.
Translate every command like this — and change nothing else:

W1. `python3 scripts/X.py ARGS` → `<PREFIX> python scripts/run.py scripts/X.py ARGS` where <PREFIX>
    is the SETUP prefix
    `Set-Location '<REPO_DIR>'; [Console]::OutputEncoding = [Text.Encoding]::UTF8; $env:PYTHONUTF8 = "1";`
    — always with that prefix and through scripts/run.py. run.py runs the script and also appends
    its output, correctly encoded, to the day's log file /tmp/routine_log/YYYY-MM-DD.txt (see
    `paths`), so the site owner can read what happened even when the terminal shows "?�".
    Never pipe Korean (or any non-ASCII) text into python (`... | python ...` turns it into "?" in
    PowerShell) — write it to a file with your file tool (UTF-8) and use --file. The save scripts
    reject text with broken characters or Korean fields without any Korean letters. Arguments
    stay the same, including paths like /tmp/feed/digest.json (Python on this computer maps
    them to the work folders `paths` printed).

W2. `/home/user/Daily_Art_AI_News_Feed` means REPO_DIR. Lines that are only
    `cd /home/user/Daily_Art_AI_News_Feed` and the prefix `cd /home/user/Daily_Art_AI_News_Feed && `
    are dropped — the terminal is already in REPO_DIR. If a command says a scripts/ file is not
    found, run `Set-Location <REPO_DIR>` and repeat it.

W3. Heredocs. A command written as
        python3 scripts/X.py ARGS << 'PYEOF'      (or 'JSONEOF', 'EOF')
        ...content...
        PYEOF
    becomes: write the content (exactly, as UTF-8) to a file with your file-writing tool —
    WORK_FEED\input.txt for the main routine, WORK_UPDATES\input.txt for the updates work —
    then run `python scripts/X.py ARGS --file <that file>`. Every such command supports
    --file (routine_steps.py digest-add / article-add / agent-finish, service_updates.py save).
    Overwrite the same input file each time.

W4. Single-quoted JSON arguments (free_tools.py add ... '{...}', weekly_report.py add ... '{...}')
    must not be typed on the command line in PowerShell. Write the JSON to WORK_FREE\input.json
    or WORK_REPORT\input.json and run
        python scripts/free_tools.py add /tmp/free/entries.json --file <that file>
        python scripts/weekly_report.py add /tmp/report/entries.json --file <that file>

W5. Other shell tools:
    - `curl ...` → `curl.exe ...` with the same options (plain `curl` is a different command
      in PowerShell). To read a web page use `python scripts/read_source.py "URL" --chars 6000`
      (with the prefix) — never print a page's raw HTML.
    - `grep PATTERN` on a command's output → `| Select-String PATTERN`.
    - `cat FILE` → read the file with your file-reading tool (use the real path from `paths`).
    - Multi-line commands joined with `\` at line ends do not exist in the current files; if
      you meet one, run it as a single line.

W5b. Quoting text arguments (e.g. find_similar.py --title / --text, agent-note). PowerShell
    expands `$` inside double quotes and splits on curly quotes, so put each text argument in
    SINGLE quotes and write a single quote inside it as two single quotes:
        --title 'Epic AI 게임잼' --text 'Epic''s jam, $50k prize ...'
    Replace curly quotes (“ ” ‘ ’) in the text with plain ones first. If a command fails because
    of quoting, fix the quoting and run it again — never skip the step (STEP A2 duplicate check
    above all).

W6. Git. Skip every `if [ ! -d ... ]; then git clone ... fi` block (the repository is already
    here) and every `git config user.email` / `git config user.name` line. GITHUB_TOKEN is not
    needed — this computer's GitHub login is used. Keep `git fetch origin main`,
    `git checkout main` and `git reset --hard origin/main` (run them one per line).

=====================================================================
AGENT RULES (A) — no sub-agents: do their work yourself, in order
=====================================================================

The routine starts separate agents with "the Agent (Task) tool" and names models (haiku,
sonnet). Do not start any agent and ignore the model names. Do their work yourself:

A1. PHASE 0 Step 2: run the workdir command only. PHASE 0 Step 3 (updates agent): do NOT do
    it now.
A2. PHASE 0 Step 4: run the free-tools `due` check now and remember DUE / NOT DUE.
A3. Order of work:
      PHASE 0 → PHASE 1 up to and including VERIFY DIGEST
      → UPDATES WORK → FREE-TOOLS WORK (only if DUE) → WAIT FOR THE UPDATES AGENT → PHASE 2
    UPDATES WORK: read routine/updates_agent_prompt.txt and follow it from STEP 1 to FINISH,
    with the W rules. Its FINISH (`agent-finish updates`) creates the DONE marker.
    FREE-TOOLS WORK: read routine/free_agent_prompt.txt and follow it from STEP 1 to FINISH,
    with the W rules.
    WAIT FOR THE UPDATES AGENT: run its `agent-status` commands; they print "finished".
A4. WEEKLY REPORT (when `weekly_report.py due` prints DUE): after the
    `weekly_report.py context` step, read routine/report_agent_prompt.txt and follow it from
    STEP 1 to FINISH yourself, then continue with `apply-report` in daily_feed_prompt.txt.
A5. While doing an agent's work, that agent's own rules apply too (e.g. "do not edit files
    inside REPO, never run git" — its scripts write only to the work folders).
A6. PHASE 2's "Do NOT spawn sub-agents" stays true: process every article yourself, one at a
    time (R4). Do NOT write a batch/wrapper script (e.g. C:\tmp\do_phase2.py) that loops over the
    digest and calls article-add — run STEP 3 and the article-add command yourself for each
    article. When article-add prints REJECTED, rewrite THAT article (shorten the body, add the
    원문 line, remove \n ...) and run it again before moving on. Never write articles.json by hand.

=====================================================================
OTHER RULES
=====================================================================

T1. Web tools. "WebFetch" means your tool for reading a web page by URL (use the browser if
    that tool fails). "WebSearch" and "`site:` search" mean your Google Search tool.

T2. Context. There is no PreCompact hook here; still run `routine_steps.py publish-init` and
    `routine_steps.py publish-end` where the routine says. If your context is summarized or
    you lose track, re-read routine/daily_feed_prompt.txt and this file, look at the work
    files (digest.json and articles.json in WORK_FEED; DONE / entries.json in the other work
    folders) and continue from the step you were on — never start over from PHASE 0.

T3. COMMIT AND PUSH: do NOT run scripts/push_to_main.py (it needs a token from the Claude
    environment). Run instead:

    <PREFIX> python scripts/run.py scripts/routine_steps.py push-local

    It first checks that the routine really ran: digest.json from PHASE 1, every article saved
    with `article-add` (a hand-written articles.json is refused), the UPDATES WORK finished
    (/tmp/updates/DONE), and not suspiciously few articles for the size of the FEED SCAN.
    If it prints "PUSH REFUSED", do the missing steps it names, then run it again. Use
    `push-local --few-ok '<reason>'` only when you really checked every source and the day has
    few qualifying articles; the reason goes into the commit message.
    Then it commits data/ to main with this computer's GitHub login, pulls with rebase and
    pushes (it retries once and never force-pushes). The HARD RULE still applies: main only,
    no new branch, no pull request. If it fails, put its error in the final report.

T3b. Sources. The FEED SCAN covers about 57 feeds in English, Korean, Japanese, Chinese and
    German (The Verge, TechCrunch, GamesIndustry.biz, Kotaku, Cartoon Brew, 4Gamer, 36Kr,
    heise ...). R2 means reading EVERY line of that output for all three sections — not only
    the Korean outlets — plus the NO FEED sources by hand. Write articles in Korean whatever
    the source language. Every ★ line must end as digest-add or `routine_steps.py skip` with a
    reason; push-local refuses while any ★ item is open. "No news today" can only be concluded from
    the FEED SCAN, never from the service-update list of detect_source_changes.py.
    Never write your own script or keyword filter (e.g. a check_*.py) to narrow the candidates —
    read the FEED SCAN lines yourself. Only the repository's scripts may be run.

T3d. Two lists, two jobs — never mix them:
      FEED SCAN (scan_feeds.py, "NEWS ARTICLE CANDIDATES")   → PHASE 1 news articles, RECENCY
                                                               RULE = today or yesterday (KST)
      detect_source_changes.py check ("SERVICE UPDATE        → UPDATES WORK only ('업데이트' page),
        CANDIDATES") + service_updates.py state                its own date rule: every official
                                                               update dated on or after the date
                                                               `state` prints ("collect entries
                                                               dated ... or later") — NOT today/
                                                               yesterday
    Do not save the update list under a name like "scan_results". In the updates work, read every
    source `check` printed and save each real product update (new model, feature, integration,
    pricing, API change) of that service; a changelog entry is not "too minor" for that page.

T3c. Writing. Follow STEP 4 exactly: id like `ideogram-vector-1027`, body in the polite
    conversational tone of existing entries (~해요, ~이에요 — not ~했습니다), final paragraph
    exactly `<p>원문: <a href="URL">SOURCE NAME</a></p>`, image by the four-step rule.
    Files for --file: write them with your file tool or `[IO.File]::WriteAllText(path, text)`
    (UTF-8); the scripts accept a BOM.

T4. Never stop early to ask anything. When a step fails, do what the routine says for that
    failure (skip the article, mark the source unreachable, restore and continue, ...).
    Terminate early only where the routine says to terminate.
