STEP 4 — FIELD MAPPING

Using the fetch results from STEP 3, convert each digest article into a
JSON entry following these rules.

  id           : Pattern `{topic-keyword}-{MMDD}`. Lowercase ASCII letters,
                 digits, and hyphens only. Combine 2–3 of the most distinctive
                 proper nouns from the headline.
                 Examples: capcom-gemini-playtesting-0423,
                           openai-sora-shutdown-0426

  tab          : "games" | "industry" | "art" — MUST equal the section's tab
                 value from STEP 2. Do not infer from URL or topic.

  headline     : Use the digest title_ko as-is.

  summary      : Single-line Korean summary, around 50 characters, based on
                 the first sentence. End with a complete sentence — no ellipsis.

  body         : Korean HTML string, 600–800 Korean characters, written in
                 polite conversational tone (~해요, ~이에요) matching existing
                 entries in data/articles/.

                 Source-text priority (use the FIRST that meets the bar):
                   1. FETCH_TEXT, if it is 200 characters or more
                   2. WEBFETCH_OUTPUT, if FETCH_TEXT was under 200 chars
                   3. The digest summary_ko text, if both above are unavailable
                      or under 200 chars

                 Focus on the core: what happened, why it matters, what impact
                 it has. Readers should fully understand without reading the
                 original. Wrap paragraphs in <p>...</p>. Use 2–3 paragraphs.
                 Append the attribution line as the final paragraph:

                   <p>원문: <a href="{url}">{source}</a></p>

                 Use double quotes for HTML attributes. No \n line breaks.
                 The 600–800 char count covers the body paragraphs and
                 EXCLUDES the attribution line.

  source       : Outlet name from the digest source_name.
                 Remove emojis and special characters
                 (e.g. "📰 TechCrunch" → "TechCrunch").

  publishedAt  : Today's date in YYYY.MM.DD format (e.g. 2026.04.28). The
                 update script fills this automatically — do not include it
                 in the JSON entry you save.

  hue          : OPTIONAL. Leave it out — the save command uses the tab's default
                 (games 200, industry 30, art 290).

  url          : The primary source URL from the digest article (source_url,
                 with https://).

  urls         : OPTIONAL. Additional links from the digest article
                 (extra_links — i.e. starting from the SECOND link), formatted as
                 [{ "label": "...", "href": "https://..." }, ...].
                 label MUST be 1–2 Korean words. Examples: 관련 보도, 공식 발표,
                 깃허브, 논문, 영상, 보도자료, 공식 사이트. Do not exceed 2 words.
                 OMIT this field entirely if there are no additional links.

  keywords     : List of sub-category labels for this article, chosen ONLY
                 from this tab's list printed by SETUP Step 3 (exact labels,
                 copied character for character), or a keyword you add under
                 "Adding a keyword" below. Pick every keyword whose
                 note fits the article's MAIN subject; for a company / program
                 / service name, pick it only when that company or product is
                 a main subject of the article — not when it is merely listed,
                 compared or mentioned in passing. Usually 1–4 keywords. Use
                 [] when none fits; never stretch a keyword to fill the list.

                 Adding a keyword — only when ALL of these hold:
                   - The article's MAIN subject is a company, program, service
                     or production target (2D/3D/animation/sound/…) — or, for
                     the industry tab only, a recurring industry topic — that
                     no keyword in this tab's list already covers.
                   - It is a general, recurring subject that future articles
                     will also be about (a major company or a widely used
                     tool) — not a one-off paper, small startup, single game
                     title or feature name.
                   - It is not a variant of an existing keyword (PlayStation
                     belongs to Sony, Xbox to Microsoft, DeepMind to Google,
                     MetaHuman to Unreal Engine, Nano Banana to Gemini).
                 At most 2 new keywords per routine run in total. Label style:
                 the official English name for companies / programs /
                 services (e.g. "Houdini"), short Korean for targets and
                 topics (e.g. "음악·사운드"). Add it BEFORE saving the article:

                   cd /home/user/Daily_Art_AI_News_Feed
                   python3 scripts/add_keyword.py --tab [games|industry|art] --label "[label]" --kind [company|product|target|topic] --match "[English name],[Korean name]" --desc "[when it applies — targets/topics only]"

                 The script adds the keyword to data/keywords.json and
                 /tmp/feed/keywords.json and tags matching past articles in
                 that tab (it prints them). If it prints REJECTED because the
                 label already exists, use the existing label instead. The
                 site shows a keyword only once 6+ articles in the tab have it,
                 so a new keyword may stay hidden for a while — that is fine.

  image        : OPTIONAL but strongly preferred. Try the four steps below in
                 order and use the FIRST URL that succeeds.

                 1st — Embedded image from the digest itself.
                       If the digest article's image_url is a non-empty
                       external URL (not "NO_IMAGE"), use that URL as-is.

                 2nd — FETCH_IMAGE from STEP 3.
                       If the 1st failed, use FETCH_IMAGE.
                       If FETCH_NEEDS_WEBFETCH_IMAGE is true or
                       FETCH_IMAGE is absent (NO_IMAGE), move to 3rd.

                 3rd — Hero image extracted from WEBFETCH_OUTPUT.
                       If the 2nd failed, search WEBFETCH_OUTPUT for a hero
                       image. If WEBFETCH_OUTPUT was not produced earlier,
                       run WebFetch ONCE here to obtain it.
                       How to find the hero image:
                       - First ![alt](https://...) pattern near the headline
                         or top of the body.
                       - Must be a .jpg / .jpeg / .png / .webp URL.
                       - Skip site logos, author avatars, ad placeholders.
                       - Skip social media icons (small, in header/footer).
                       - Skip tracking pixels (1x1) and decorative SVG icons.

                 4th — Omit field (hue gradient fallback).
                       If all three above fail, omit the image field entirely.
                       The site renders a gradient using the hue value.
                       Do NOT write image: "" or image: null.
