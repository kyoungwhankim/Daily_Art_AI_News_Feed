PROCESS ARTICLES

This section reads today's curated article list from the digest, fetches each
source page, and saves a JSON entry per article into /tmp/feed/articles.json.
Run STEP 1 through STEP 4 in order.

---

STEP 1 — LOAD THE DIGEST

  python3 << 'PYEOF'

If the script prints "No articles in digest today.", terminate the routine —
there is nothing to publish.

---

STEP 2 — MAP DIGEST ENTRIES INTO SECTIONS

Process articles grouped by section in the order 1 → 2 → 3, and within each
section in the order they appear in digest.json.

  | digest "section" | Section heading      | tab value   |
  |------------------|----------------------|-------------|
  | 1                | 🎮 게임 제작 속 AI     | "games"     |
  | 2                | 🏢 AI 도입            | "industry"  |
  | 3                | 🎨 아트 전반 AI 소식   | "art"       |

Build an internal list of articles to process. For each article record:
  - tab          (from the digest "section" via the table above)
  - headline     = digest "title_ko"
  - source url   = digest "source_url"; source name = digest "source_name"
  - embedded image URL = digest "image_url" (ignore if empty or "NO_IMAGE")
  - additional links   = digest "extra_links" in order (i.e. the links after
                         the source link — the SECOND link onwards)
  - fallback text for STEP 4 = digest "summary_ko" (the 3 sentences joined)

Every article must inherit its section's tab — do not infer tab from URL or
topic.

---

STEP 3 — FETCH SOURCE ARTICLE (run exactly once per article)

For each article in your parsed list, run the fetch script ONE TIME. The
output is shared by both the body and image field mappings in STEP 4 — do
not run it again later.

  python3 scripts/fetch_article.py "ARTICLE_URL"

The script prints these lines (Routine depends on this exact format):

  OG_IMAGE: <url-or-NO_IMAGE>
  LINK: <url>          (zero or more)
  ---ARTICLE_TEXT---
  <body text>
  ---NEEDS_WEBFETCH_FOR_IMAGE---       (only if curl succeeded but image extraction failed)

If the script prints CURL_FAILED instead, retry the same URL ONE TIME using
the WebFetch tool. The WebFetch markdown output is likewise shared by both
the body and image field mappings — do not refetch later.

Read up to 8,000 characters after ---ARTICLE_TEXT--- and store the results
under these names so you can reference them in STEP 4:

  | Variable                     | Content                                    |
  |------------------------------|--------------------------------------------|
  | FETCH_TEXT                   | Body text after ---ARTICLE_TEXT--- (≤8000) |
  | FETCH_IMAGE                  | Value from OG_IMAGE: (NO_IMAGE → absent)   |
  | FETCH_LINKS                  | List of URLs from LINK: lines              |
  | FETCH_NEEDS_WEBFETCH_IMAGE   | Whether ---NEEDS_WEBFETCH_FOR_IMAGE--- was printed |
  | WEBFETCH_OUTPUT              | Full markdown output from WebFetch (if used) |

⚠️  STEP 3 IS MANDATORY FOR EVERY ARTICLE — NO EXCEPTIONS.
Even though the digest already contains summary text, you MUST run
fetch_article.py to obtain og:image, extra links, and clean source body text.
Skipping this step means image and urls fields will be missing from the
output.

---

STEP 4 — FIELD MAPPING

Using the fetch results from STEP 3, convert each digest article into a
JSON entry following these rules.

  id           : Pattern `{topic-keyword}-{MMDD}`. Lowercase ASCII letters,
                 digits, and hyphens only. Combine 2–3 of the most distinctive
                 proper nouns from the headline.
                 Examples: capcom-gemini-playtesting-0423,
                           openai-sora-shutdown-0426

  tab          : "games" | "industry" | "art" — MUST equal the section's tab
                 value from STEP 2. Do not infer from URL or topic.

  headline     : Use the digest title_ko as-is.

  summary      : Single-line Korean summary, around 50 characters, based on
                 the first sentence. End with a complete sentence — no ellipsis.

  body         : Korean HTML string, 600–800 Korean characters, written in
                 polite conversational tone (~해요, ~이에요) matching existing
                 entries in data/articles/.

                 Source-text priority (use the FIRST that meets the bar):
                   1. FETCH_TEXT, if it is 200 characters or more
                   2. WEBFETCH_OUTPUT, if FETCH_TEXT was under 200 chars
                   3. The digest summary_ko text, if both above are unavailable
                      or under 200 chars

                 Focus on the core: what happened, why it matters, what impact
                 it has. Readers should fully understand without reading the
                 original. Wrap paragraphs in <p>...</p>. Use 2–3 paragraphs.
                 Append the attribution line as the final paragraph:

                   <p>원문: <a href="{url}">{source}</a></p>

                 Use double quotes for HTML attributes. No \n line breaks.
                 The 600–800 char count covers the body paragraphs and
                 EXCLUDES the attribution line.

  source       : Outlet name from the digest source_name.
                 Remove emojis and special characters
                 (e.g. "📰 TechCrunch" → "TechCrunch").

  publishedAt  : Today's date in YYYY.MM.DD format (e.g. 2026.04.28). The
                 update script fills this automatically — do not include it
                 in the JSON entry you save.

  hue          : Integer 0–360. Use the tab default when no image is present:
                   games    → 200
                   industry → 30
                   art      → 290
                 When an image is present, the default value is still fine to
                 keep. You may also pick a hue that varies from neighboring
                 articles in the same tab using this rough guide:
                   tech / corporate / blue : 200–240
                   games / energetic       : 20–50 or 300–340
                   art / museums / soft    : 260–290 or 40–80
                   policy / serious        : 0–20 or 340–360
                   nature / sustainability : 90–150

  url          : The primary source URL from the digest article (source_url,
                 with https://).

  urls         : OPTIONAL. Additional links from the digest article
                 (extra_links — i.e. starting from the SECOND link), formatted as
                 [{ "label": "...", "href": "https://..." }, ...].
                 label MUST be 1–2 Korean words. Examples: 관련 보도, 공식 발표,
                 깃허브, 논문, 영상, 보도자료, 공식 사이트. Do not exceed 2 words.
                 OMIT this field entirely if there are no additional links.

  keywords     : List of sub-category labels for this article, chosen ONLY
                 from this tab's list printed by SETUP Step 3 (exact labels,
                 copied character for character). Pick every keyword whose
                 note fits the article's MAIN subject; for a company / program
                 / service name, pick it only when that company or product is
                 a main subject of the article — not when it is merely listed,
                 compared or mentioned in passing. Usually 1–4 keywords. Use
                 [] when none fits; never stretch a keyword to fill the list,
                 and never invent a new one.

  image        : OPTIONAL but strongly preferred. Try the four steps below in
                 order and use the FIRST URL that succeeds.

                 1st — Embedded image from the digest itself.
                       If the digest article's image_url is a non-empty
                       external URL (not "NO_IMAGE"), use that URL as-is.

                 2nd — FETCH_IMAGE from STEP 3.
                       If the 1st failed, use FETCH_IMAGE.
                       If FETCH_NEEDS_WEBFETCH_IMAGE is true or
                       FETCH_IMAGE is absent (NO_IMAGE), move to 3rd.

                 3rd — Hero image extracted from WEBFETCH_OUTPUT.
                       If the 2nd failed, search WEBFETCH_OUTPUT for a hero
                       image. If WEBFETCH_OUTPUT was not produced earlier,
                       run WebFetch ONCE here to obtain it.
                       How to find the hero image:
                       - First ![alt](https://...) pattern near the headline
                         or top of the body.
                       - Must be a .jpg / .jpeg / .png / .webp URL.
                       - Skip site logos, author avatars, ad placeholders.
                       - Skip social media icons (small, in header/footer).
                       - Skip tracking pixels (1x1) and decorative SVG icons.

                 4th — Omit field (hue gradient fallback).
                       If all three above fail, omit the image field entirely.
                       The site renders a gradient using the hue value.
                       Do NOT write image: "" or image: null.

Save each completed article object to /tmp/feed/articles.json:

  python3 << 'PYEOF'
  import json
  article = {
      "id": "[topic-keyword-MMDD]",
      "tab": "[games | industry | art]",
      "headline": """[digest title_ko 그대로]""",
      "summary": """[한국어 50자 안팎, 마침표 포함]""",
      "body": (
          "<p>[1문단 — 무슨 일이 있었는지 / 핵심 사실]</p>"
          "<p>[2문단 — 배경, 맥락, 영향]</p>"
          '<p>원문: <a href="ARTICLE_URL_HERE">SOURCE_NAME_HERE</a></p>'
      ),
      "source": "[출처 매체명, 이모지 제거]",
      "hue": 200,
      "keywords": [],  # 이 탭 KEYWORD LIST의 label만 (없으면 빈 리스트)
      "url": "[원문 기사 URL]",
      "urls": [
          # {"label": "관련 보도", "href": "https://..."},
      ],
      "image": "[image URL or omit field]",
  }
  # Length / format checks (EXECUTION RULE R6) — do not edit.
  import re
  _paras = re.sub(r'<p>원문:.*?</p>', '', article["body"])
  _text = re.sub(r'<[^>]+>', '', _paras)
  problems = []
  if not 600 <= len(_text) <= 800:
      problems.append(f"body is {len(_text)} chars (incl. spaces, without the "
                      f"원문 line); it must be 600–800")
  if '<p>원문: <a href="' not in article["body"]:
      problems.append("body is missing the final 원문 attribution paragraph")
  if "\n" in article["body"]:
      problems.append("body contains \\n line breaks")
  for k in ("id", "tab", "headline", "summary", "source", "url"):
      if not article[k] or str(article[k]).startswith("["):
          problems.append(f"{k} is empty or still a placeholder")
  if article["tab"] not in ("games", "industry", "art"):
      problems.append("tab must be games, industry or art")
  with open('/tmp/feed/keywords.json') as f:
      _allowed = json.load(f).get(article["tab"], [])
  if not isinstance(article.get("keywords"), list):
      problems.append("keywords must be a list (use [] when none fits)")
  else:
      _bad = [k for k in article["keywords"] if k not in _allowed]
      if _bad:
          problems.append(f"keywords {_bad} are not in the {article['tab']} "
                          f"KEYWORD LIST — use exact labels from SETUP Step 3")
  if problems:
      print("REJECTED:", "; ".join(problems))
      raise SystemExit(1)

  if not article.get("urls"):
      article.pop("urls", None)
  if (not article.get("image") or article["image"].startswith("[")
          or article["image"] == "NO_IMAGE"):
      article.pop("image", None)
  with open('/tmp/feed/articles.json') as f:
      articles = json.load(f)
  articles.append(article)
  with open('/tmp/feed/articles.json', 'w') as f:
      json.dump(articles, f, ensure_ascii=False, indent=2)
  print(f"Saved article {len(articles)}: [{article['tab']}] "
        f"{article['headline'][:40]}... keywords={article['keywords']}")
  PYEOF

UPDATE THE FEED DATA IN THE REPOSITORY

This step adds the new articles to today's date file
(data/articles/YYYY-MM-DD.json), deduplicating against URLs already present in
any date file (so that the same article cannot be republished on consecutive
days).

cd /home/user/Daily_Art_AI_News_Feed
python3 scripts/update_articles.py

The script:
- Reads existing ids and urls from every file in data/articles/ for
  uniqueness checks
- Skips any new article whose url is already present (URL dedup; scheme,
  www., trailing '/' and #fragment differences count as the same URL)
- Adds each new article to today's date file, ahead of that tab's existing
  entries for today (creates the file if this is the first run today)
- Generates a unique slug id for each new entry if one is missing
- Fills publishedAt with today's KST date in YYYY.MM.DD format
- Keeps each article's keywords (drops any label missing from the tab's list
  in data/keywords.json, with a warning)
- Regenerates data/index.json (the list of date files the site loads)
